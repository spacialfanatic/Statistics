Public-key cryptography / An interactive notebook

A small curve.
A big cryptographic idea.

Turn a private number into a public point. Explore elliptic-curve scalar multiplication, inspect its statistical behaviour, and connect the experiment to Ethereum.

Scalar multiplication is not a hash function. Q = kG is deterministic and efficiently computable. Reversing it is difficult on suitable real-world curves.
01 / The experiment

Private key → public key

Our curve is y² ≡ x³ + 7 (mod 17), with base point G = (1, 5). Since 5² ≡ 1³ + 7 ≡ 8 (mod 17), G lies on the curve.

Choose a toy private key

Use 1–8: G has order 9. Thus 9G = O, the identity (point at infinity). The toy subgroup has composite order and is unsuitable for cryptography.

    What should we conclude?

    Determinism: the same k always gives the same Q.

    Uniform keys → uniform points: k ↦ kG is a bijection between 1–8 and the nonidentity points of the subgroup generated by G. Coordinates themselves are not uniform over 0–16: Q and −Q share x.

    No full-point collisions in this domain: collisions occur if unrestricted integers are allowed, because (k + 9)G = kG. Equal x-values alone are not equal public keys.

    Statistical tests cannot prove security. A flat histogram neither establishes ECDLP hardness nor guarantees unpredictability.

    One-bit sensitivity: a small, honest experiment

    Flip each of the 4 bits of every valid k; retain pairs where the changed key is also in 1–8 and count each unordered pair once. Encode Q as 5-bit x followed by 5-bit y, then measure Hamming distance. This is an encoding-dependent descriptive test, not evidence of a cryptographic hash’s avalanche property.

    Adjacent keys also satisfy (k + 1)G = kG + G. Scalar multiplication has algebraic structure; it is not a random oracle.

    03 / From toy curve to blockchains

    The same idea, at a different scale.

    Real secp256k1 uses y² = x³ + 7 over the prime field p = 2²⁵⁶ − 2³² − 977, a specified generator, and a large prime subgroup order n. Our modulus 17 and G = (1,5) are only a teaching analogue—not secp256k1. Generic discrete-log attacks on the real subgroup take roughly 2¹²⁸ group operations. [1]

    Ethereum’s externally owned accounts

    private scalar k → public point Q = kG → Keccak-256(x ∥ y) → last 20 bytes

    The first arrow is elliptic-curve multiplication. The second is hashing. For address derivation, x and y are each 32 bytes; the 0x04 uncompressed-key prefix is excluded. Ethereum uses ECDSA signatures to authorize EOA transactions. The address is not the public key. This lab computes only a toy public point. [2]

    04 / Under the hood

    How point addition works

    All arithmetic is modulo 17. Division means multiplication by a modular inverse; it is not ordinary decimal division.

    Formulas and exceptional cases
    For P = (x₁,y₁), R = (x₂,y₂):
P ≠ R: λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ mod 17
P = R: λ = 3x₁² · (2y₁)⁻¹ mod 17
x₃ = λ² − x₁ − x₂ mod 17
y₃ = λ(x₁ − x₃) − y₁ mod 17

Identity: P + O = P
Inverse points: (x,y) + (x,−y) = O
Doubling a point with y = 0 also gives O.
    Algorithm and computational cost

    The animation starts at O and repeatedly adds G, requiring k additions to display every multiple. The code also includes double-and-add, which computes kG in O(log k) group operations. JavaScript Number is sufficient for this tiny field, but cannot represent real secp256k1 integers exactly; real arithmetic needs BigInt or a vetted library.

    Experiment limitations
    The curve has 18 points including O; G generates a subgroup of 9 points (8 finite points and O). The keyspace is tiny and the order is composite. Key entropy is at most 3 bits, and enumerating the table recovers any toy private key. The statistical sample uses a sound random source, but that cannot make this group secure. Do not enter or generate real wallet secrets here.
    The x-coordinate chi-square statistic uses the exact induced coordinate distribution, not a uniform 17-bin null hypothesis. Only positive-probability bins are included. It is reported descriptively without a p-value; repeated reruns and dependent projections are not security proofs.
