01 / Encrypt & decrypt

The same message, two different mechanisms.

Caesar shifts letters directly. The elliptic-curve construction establishes a shared secret, derives a symmetric key, and encrypts the UTF-8 message with AES-GCM.

No data is sent anywhere. ECC encryption requires browser Web Crypto: use a modern browser opening this file directly, or serve it over HTTPS / localhost. Caesar and its analysis work without Web Crypto.

secp256k1 hybrid

PUBLIC-KEY + SYMMETRIC
Contains Q, R, salt, IV, and ciphertext with a 128-bit authentication tag. No private scalar or derived AES key is included.

Encrypt a message first.
Follow the algorithm and the role of each key
  1. Recipient key generation: choose a secret d uniformly from 1–N; compute public Q = dG. For real deployments, choose d from 1–n−1 with a cryptographic random generator.
  2. Sender’s fresh key: choose a new random r from 1–n−1 for every encryption and publish R = rG. The sender only needs the recipient’s public Q.
  3. Shared secret: sender computes S = rQ. Recipient computes S′ = dR. They agree because r(dG) = d(rG). Neither d nor r is sent.
  4. Key derivation: feed the 32-byte, big-endian x-coordinate of S to HKDF-SHA-256 with a fresh 16-byte salt. The context includes the protocol label and encodings of R and Q. Derive a 256-bit AES key K.
  5. Encrypt: AES-256-GCM encrypts the UTF-8 message with K and a random 12-byte IV. The context is also authenticated as additional data. Send Q, R, salt, IV, ciphertext and tag.
  6. Decrypt: validate the public points, confirm Q = dG, recompute dR and K, then authenticate and decrypt. An altered packet or wrong key is rejected.

This is a teaching hybrid inspired by ECIES, with an explicitly chosen HKDF / AES-GCM format; it is not a claim of compatibility with a particular ECIES standard. AES provides message encryption; ECC provides key agreement. Neither key generation nor hashing alone encrypts a message.

The statistical model, equations and pseudocode

Convert the training corpus to uppercase A–Z, discarding all other characters. For this analysis, accented letters are excluded rather than transliterated. If Cᵢ is the corpus count of letter i and L is the total, use Laplace smoothing: pᵢ = (Cᵢ + 1) / (L + 26). Smoothing prevents zero expected counts.

For each candidate shift s = 0, 1, ..., 25:
    candidate = CaesarDecrypt(ciphertext, s)
    O[i] = number of occurrences of letter i in candidate
    M = number of A–Z letters in candidate
    expected[i] = M * p[i]
    chi_squared[s] = sum((O[i] - expected[i])² / expected[i])
Return the shift with the smallest score (ties: smallest shift).

The optional bigram model counts adjacent letters in the letter-only corpus, including across removed word boundaries. With α = 0.2, P(b|a) = (Cₐᵦ + α) / (Σⱼ Cₐⱼ + 26α). It scores the first letter with pᵢ and subsequent letters by conditional probability; the reported score is negative log₂ likelihood divided by the number of letters (bits per letter). Lower is better. It uses order, which unigram frequencies ignore.

The χ² value is a ranking heuristic here. On short texts, expected counts are often too small for an asymptotic goodness-of-fit test. No p-value is computed. Both methods cost O(26M) for a text of M letters; 26 is constant.

Experimental design, test text and limitations

The six lengths are 10, 25, 50, 100, 250 and 500 letters. A fixed pseudorandom generator selects offsets and encryption keys for reproducibility; it is used only for the benchmark, never for ECC key generation. The plaintext corpus used for model training is separate from this test text. The attacker does not see the true shift while scoring. Both scorers receive identical ciphertexts.

Windows can overlap and all come from one small source. These trials therefore do not establish independent, population-wide success probabilities. Larger samples usually stabilize letter proportions, but recovery need not improve monotonically for every text. Names, code, poetry, repeated letters, unusual vocabulary, wrong-language models and distribution mismatch can all defeat the ranking. A bigram model may help when language patterns match, but can overfit a small corpus.

At least 500 A–Z letters are required. Replace this text to test another genre or language. Changing either corpus marks previous measurements as stale; retrain before running if you changed the training corpus.
04 / Attack the restricted ECC key

A 256-bit curve cannot rescue a 12-bit secret.

The attacker knows the recipient’s public Q and that 1 ≤ d ≤ N. Enumerate candidate multiples of G until a full point matches Q. This attack needs no language statistics and no guessed plaintext.

Incremental enumeration uses at most N point comparisons and N−1 additions, O(N) time and O(1) auxiliary search memory. It avoids recomputing every multiple from scratch. For uniformly distributed d, the expected number of candidate checks is (N + 1)/2.

A match is exact because multiplication by G is injective on 1–N when N < n. Matching only x would also accept the negative point; this implementation compares both coordinates.

The bound is attacker knowledge. Set it below d to observe “not found.” A fresh random sender key r and a 256-bit AES key do not expand the recipient’s tiny secret space.

Alternative attacks and design weaknesses

Baby-step giant-step: solve the bounded discrete log in O(√N) time and O(√N) memory by tabulating small multiples and matching giant steps. Pollard’s kangaroo also exploits a known interval with roughly O(√N) work and low memory. An interval containing 4,096 candidates is tiny even before considering these improvements.

Full-size keys: enumerating approximately 2²⁵⁶ candidates is infeasible. Generic classical algorithms such as Pollard rho improve this to approximately √n ≈ 2¹²⁸ group operations, still infeasible at conventional scales. A 256-bit private scalar does not mean 256-bit resistance to generic discrete-log attacks.

What belongs to the restricted range? Direct private-key enumeration and bounded discrete-log attacks exploit low key entropy. They do not demonstrate a flaw in the secp256k1 curve. Nonuniform or predictable full-size scalars can also reduce effective entropy.

What belongs to the construction or implementation? A raw shared coordinate is not a suitable general-purpose message cipher. Reusing an AES-GCM key/IV pair can be catastrophic; poor randomness, omitted point validation, missing integrity protection and side-channel leakage introduce separate weaknesses. This page uses fresh randomness, validates finite on-curve points, derives keys and authenticates ciphertext, but its handwritten BigInt arithmetic is variable-time and unaudited. It is an educational implementation, not production cryptography.

Authentication boundary: a valid GCM tag detects tampering under the derived key; it does not identify the sender. Anyone knowing Q can create a valid new encryption. Public keys must be authenticated out of band to avoid substitution attacks. The page makes no sender-signature claim and does not provide forward secrecy against later compromise of the recipient’s static d.

Main conclusion. Caesar leaks the structure of the message itself. The restricted ECC example leaks an efficiently checkable key hypothesis through its public key. Statistics helps select a Caesar plaintext; exact group equality certifies the bounded ECC key.
06 / Implementation notes & sources

Open the hood.

Actual curve parameters and point arithmetic

The curve is y² ≡ x³ + 7 (mod p), a = 0, b = 7, cofactor h = 1. The public points are encoded as uncompressed SEC 1 points: 04 || x || y, with 32 bytes per coordinate. Integers are stored as JavaScript BigInt; ordinary Number cannot represent these values exactly.

For distinct points, λ = (y₂−y₁)(x₂−x₁)⁻¹ mod p. For doubling, λ = 3x₁²(2y₁)⁻¹ mod p. Then x₃ = λ²−x₁−x₂ mod p and y₃ = λ(x₁−x₃)−y₁ mod p. Inverse points sum to the identity O; O is represented by null. Double-and-add needs O(log d) group operations to compute dG.
Point decoding checks finite coordinates in [0,p−1] and the curve equation. On this specific cofactor-one, prime-order curve, a finite on-curve point is in the intended subgroup. This reasoning does not transfer automatically to arbitrary curves.


Measured entropy and index of coincidence
For observed letter proportions fᵢ, empirical entropy is H = −Σ fᵢ log₂ fᵢ. The index of coincidence is IC = Σ Oᵢ(Oᵢ−1) / [M(M−1)] for M ≥ 2. Caesar only permutes Oᵢ, so both quantities are invariant. Neither statistic alone determines the shift.
For randomized encrypted bytes, a sample histogram can look approximately flat, but small samples fluctuate. Encoding ciphertext as hexadecimal creates a different alphabet of only 16 symbols; those character frequencies are not plaintext-letter frequencies. No claim of security follows from either histogram.
